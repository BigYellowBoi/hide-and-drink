# Media in Cloudflare R2: setup

Photos and videos (answer photos, drink proofs, curse proofs, media sent with a card) are stored in a Cloudflare R2 bucket as the original files the phone hands over. No 48 MB limit and no re-encoding, within a storage budget that keeps the bucket inside R2's free plan.

Status: done (19/11/26). Bucket `hide-and-drink-media`, CORS set for the Pages site, the four `R2_*` secrets are in Supabase. This page records how, for a rebuild or a second city's project.

## How it works

- **Upload.** The phone asks the Edge Function `media-upload-url` (with its Supabase session) for a short-lived (15 min) presigned PUT for `<game_id>/<folder>/<file>.<ext>`, where the folder is the question, proof or card the file belongs to. The function calls `media_upload_grant` (migration `20261222090000_r2_media.sql`), which checks the caller is a player allowed to attach media there right now (the same rules as the old Storage policies: a hider for a pending photo question; the owing team for an open proof; a hider for a card in the hand), checks the size and type, and reserves room in the budget. The phone PUTs the file straight to R2 with a progress bar, retrying up to 3 times with a fresh URL, then calls the function again with `done: true`. The function checks R2 has the object (HEAD) and records its real size. Only then do `answer_question`, `submit_drink_proof` and `play_card` accept the name.
- **Read.** `PhotoThumb` asks `media-read-url` for read URLs (1 h), batched. `media_read_grant` returns only names the caller's team may see: a file is readable if an event the team can see names it (`drink_proved` path, a photo question's answer), or the team may upload it right now. So a hider-only cost photo never gets a URL for a seeker. The Supabase buckets' Storage policies now use the same rule. Files still in the Supabase buckets get a signed Storage URL from the same function.
- **Fallbacks.** Without the four R2 secrets (or if the functions aren't deployed or can't be reached) the phone uses the old path: photos shrunk to 1600 px JPEG, videos over 48 MB squeezed to 480p, uploaded to the Supabase buckets. Media already in those buckets keeps working.
- **Logging.** The size, type, name and user agent of every picked file are logged by the phone (`[media] picked ...` in the console), by the function (Edge Function logs: `media upload requested`), and kept in `media_objects.picked`. Use them to check whether iPhones hand over originals or converted copies:

  ```sql
  select created_at, quality, bytes, picked ->> 'bytes' as picked_bytes, picked ->> 'type' as type, picked ->> 'user_agent' as phone
    from public.media_objects order by created_at desc limit 20;
  ```

## Staying free

R2's free plan: 10 GB-month of storage, 1 million writes and 10 million reads a month, no egress fees. The functions enforce:

| Rule | Default | Override (Edge Function secret) |
| --- | --- | --- |
| Total bytes in R2 (uploaded plus reservations of the last 20 min) | 9 GB | `R2_BUDGET_BYTES` (capped at 9.5 GB whatever it says) |
| One file (reduced-quality videos past it are squeezed instead of refused) | 2 GB | `R2_MAX_FILE_BYTES` |
| Reduced-quality videos stay original only below this share of the budget | 0.5 | `R2_REDUCED_SHARE` |

- **Full quality:** every photo, and every video unless its card says otherwise (Sculling: people and drinks).
- **Reduced quality:** videos for cards with `params.video_quality` = `reduced` (Bird Guide; set in the card editor under "Video quality"). While R2 holds less than half the budget they stay original too; past that the phone squeezes them to 480p before uploading.
- **4K:** iPhones on 4K 30 fps record about 170 MB a minute (60 fps: about 400 MB). A typical round (about 35 photos and a Sculling pair) is about 0.3 GB; a full-quality Bird Guide pair up to about 1.7 GB, so 9 GB lasts roughly 15 to 30 rounds. A 5 min bird at 4K 60 fps passes 2 GB: it is squeezed rather than refused.
- **Budget reached:** uploads go to the Supabase buckets instead (shrunk, as before), so nothing can push R2 past the free plan.
- Reservations nobody confirmed are checked against R2 after 20 minutes (on the next upload): counted if the file arrived, dropped if not. An object bigger than it was declared is deleted.
- Nothing is deleted automatically. To free room, delete a finished game's folder (`<game_id>/`) in the R2 dashboard, then its rows: `delete from public.media_objects where game_id = '<game_id>';`. Check usage with `select pg_size_pretty(sum(bytes)) from public.media_objects where uploaded_at is not null;` and in the R2 dashboard (Metrics).
- Optional belt and braces: Cloudflare dashboard > Notifications > R2 storage usage alert below 10 GB.

## One-time setup

1. **Cloudflare account.** Sign up at dash.cloudflare.com (free). R2 > Overview > enable R2. Cloudflare asks for a card to enable R2 even on the free plan; the budget above keeps usage within the free allowance.
2. **Bucket.** R2 > Create bucket: name `hide-and-drink-media`, location Automatic, Standard storage class (Infrequent Access is not free). Leave public access off: every read goes through a presigned URL.
3. **API token scoped to the bucket.** R2 > Manage R2 API tokens > Create API token: permission **Object Read & Write**, "Apply to specific buckets only" > `hide-and-drink-media`, no expiry (or note the date). Copy the **Access Key ID** and **Secret Access Key** (shown once) and the **Account ID** (R2 overview, right-hand side).
4. **Bucket CORS.** Bucket > Settings > CORS policy:

   ```json
   [
     {
       "AllowedOrigins": ["https://bigyellowboi.github.io", "http://localhost:5173"],
       "AllowedMethods": ["GET", "PUT", "HEAD"],
       "AllowedHeaders": ["content-type"],
       "ExposeHeaders": ["ETag"],
       "MaxAgeSeconds": 3600
     }
   ]
   ```

5. **Supabase secrets** (Project Settings > Edge Functions > Secrets, or the CLI):

   ```bash
   supabase secrets set R2_ACCOUNT_ID=<account id> R2_ACCESS_KEY_ID=<access key id> R2_SECRET_ACCESS_KEY=<secret> R2_BUCKET=hide-and-drink-media
   ```

6. **Deploy the functions** (as `send-push`, from the repo root; they keep `verify_jwt = true` from `supabase/config.toml`, so only signed-in phones can call them). Redeploy after changing a secret:

   ```bash
   supabase functions deploy media-upload-url
   ```

   ```bash
   supabase functions deploy media-read-url
   ```

The migration deploys with the rest on merge to `main`. Until the functions are deployed the app keeps using the Supabase buckets.

## Notes

- iPhone: Safari's file picker may convert HEIC photos to JPEG and offer a "compressed" video. The picker box shows the picked size and type, and the logs above record it. A photo in a format other browsers can't show (HEIC) is converted to a full-size JPEG on the phone.
- A 2 GB upload on mobile data takes a while: keep the app open. The upload is one PUT; a failure retries from the start (up to 3 more times), then shows the error, and tapping Send again retries. A file already uploaded isn't sent again when only the action failed.
- Rotating the API token: create a new one, `supabase secrets set` the two keys, delete the old token.
