# Hide + Drink

Companion web app for our friend group's "Hide + Drink" variant of Jet Lag: The Game Hide and Seek. The hider hides at a bar; cards and curses are drinking themed. Private game, ~6 players (one hider team, one seeker team, ~3 each). Brisbane first, then Sydney.

Full spec: `docs/spec.md`. Design (colours, fonts, logos, screens): `docs/design.md`; follow it for any UI work. Seed data: `data/`. Read only the parts relevant to the current task.

## Non-negotiables

1. **Live sync, server-authoritative.** Phones never mutate game state. They call a game action function; the server validates against current state, writes in one transaction, assigns the next sequence number, then broadcasts. Every phone applies events in sequence order and fetches gaps.
2. **Resync on reopen.** On visibility change/reconnect, fetch all events after the last seen seq before allowing any action. Block actions while disconnected; never queue actions offline.
3. **Server time for every timer.** Store start + duration; clients correct for clock offset.
4. **No leaks between teams.** Hider-only data (position, chosen bar, hand, draw pile, suggested answers) goes only to the hider channel and is protected by RLS. Never send it to seekers and filter in the UI.
5. **Nothing game-content is hard-coded.** Cards, categories, questions, config and play areas are data. Code only implements the fixed set of card behaviours and question types.
6. **The hider always confirms answers manually.** The app suggests; the hider taps the final answer within the deadline.

## Stack

- Front end: React + Vite + TypeScript, installable PWA, hosted on GitHub Pages
- Map: MapLibre GL JS; drawing: Terra Draw; geometry: Turf.js
- Backend: Supabase (Postgres + PostGIS, database functions for game actions, RLS, anonymous auth, Realtime Broadcast from Database on private channels, Storage for photos)
- Data pipeline: Python (geopandas, Overpass/OSM, GTFS) in `pipeline/`
- Tests: Vitest for client logic; SQL tests for game action functions

## Conventions

- Game actions: one Postgres function per action (`ask_question`, `answer_question`, `play_card`, ...), each taking `game_id`, `client_action_id` (idempotency) and, for game-play actions, `last_seen_seq`. Pattern (see `create_game`/`update_config` in the core migration): `_require_user` → `_previous_result` → `_lock_game` → validate → `_require_fresh` → write → `_append_event` → `_record_result`. Errors are `raise exception '<snake_case_code>' using errcode = 'P0001'`.
- Library actions (`save_card`, `save_deck_preset`, ...) are not game actions: no game, no event log, still idempotent via `client_action_id`. `save_push_subscription`/`delete_push_subscription` are upserts/deletes of the caller's own rows, no `client_action_id`
- Exception: `report_position` (seeker GPS) and `report_picking` (the bar a hider has selected in the picker) are ephemeral and latest-wins: no `client_action_id`/`last_seen_seq`, not in the event log; broadcast as `position` on both team topics and `picking` on the hiders topic only. Server-derived events (e.g. `freeze_changed`) have no actor when the actor would leak who caused them.
- Every new function: `revoke execute ... from public, anon, authenticated`, then grant only client actions to `authenticated` and add them to the allow-list in `supabase/tests/03_privileges.test.sql`.
- Migrations live in `supabase/migrations/` and auto-deploy to production on merge to `main`. Never edit an applied migration; add a new one. Each migration needs its own timestamp (Supabase keys them by it; `src/lib/migrations.test.ts` checks): rebase onto main before merging if another PR added one. Seed content ships as a migration (`scripts/seed_to_sql.py`).
- Events table is append-only. Game state is derived from it or updated in the same transaction.
- Channels: `game:{id}` (everyone), `game:{id}:seekers`, `game:{id}:hiders`; `library` (any signed-in user: library and preset changes).
- Units: metres and seconds in data; display km/min.
- Keep this file short. Update it when a decision changes.

## Commands

- `npm run dev`: local dev server (needs `.env.local`, see `.env.example`)
- `npm test`: Vitest unit tests (seed data checks live in `src/lib/seed.test.ts`)
- `npm run lint`: oxlint
- `npm run build`: type-check and production build into `dist/`
- `supabase start` then `supabase test db`: apply migrations to a local Supabase stack (Docker) and run the pgTAP tests in `supabase/tests/`
- `python3 -m pipeline build <city>` then `python3 -m pipeline sql <city>`: rebuild a city pack and write its loading migration (see `pipeline/README.md`); `python3 -m pytest pipeline/tests` for pipeline tests
- `npm run latency`: latency harness, 6-10 simulated players against a running Supabase (see `scripts/latency/README.md`); CI fails if p95 > 1 s
- `scripts/test-db/run.sh`: same tests on plain Postgres with Supabase stand-ins (no Docker images needed; needs psql, pg_prove, pgTAP)
- CI (`.github/workflows/deploy.yml`) runs lint, unit tests, database tests, latency harness and build on every PR, and deploys `main` to GitHub Pages. `keep-alive.yml` queries Supabase every 3 days so the free project never pauses

## Layout

- `src/lib/supabase.ts`: Supabase client from `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`
- `src/lib/seed.ts`: typed access to `data/cards.json` and `data/questions.json`
- `src/lobby/`: lobby state derived from events (`state.ts`), the settings schema (`config.ts`: every editable config key with label, description, info, input with min/max/step, group Hiding/Questions/Cards/Vetoes and penalties/Advanced; `validateConfig` on save; keys in `NOT_SETTINGS` such as notes, penalty text and the deck are never shown and kept as they are; a new key in `data/config.json` must go in one of the two, a test checks), error messages. UI in `src/components/` (`Home`, `Lobby`, `ConfigEditor`, `JoinCode`, `Round`)
- The join code sits under the main clock in the top bar for the whole game, so anyone who drops out can rejoin
- Join links/QR open `<base>?join=CODE`, which prefills the join form. The phone keeps the game id (`hd.gameId`), name and last code (`hd.lastCode`): reopening goes straight back in, a start with no signal retries instead of failing, and `not_a_player` (lost session) offers Rejoin with the saved code and name
- Leave game in a lobby calls `leave_game` (host passes to the longest-standing player; the last one out deletes the lobby). In a running game it only forgets the game on that phone
- Push alerts: trigger on `events` queues `push_outbox` rows (questions to hiders, answers and curses to seekers, freezes to hiders, round over / next round / game over to everyone; never wider than the event's visibility; actor left out) and calls Edge Function `supabase/functions/send-push` via `pg_net` when the Vault has `push_function_url`/`push_webhook_secret`. Client: `src/lib/push.ts`, `PushToggle` (Lobby, Settings, Timeline tab), handlers in `public/push-sw.js` (imported into the generated service worker). Setup: `docs/push.md`
- Timers: `useServerNow` ticks on whole server seconds (paused while hidden); `src/lib/timers.ts` tones (amber under 1 min, pulse under 10 s), overdue "+m:ss"; `useTimerAlert` buzzes at 1 min and 0 (main clock, hider's answer deadline)
- Seekers get `SeekerNotices` (pinned, OK to dismiss, per phone): each answer and each curse cast. The Timeline tab gets a yellow dot for entries others caused since this phone last looked (`useTimelineUnseen`)
- `src/sync/`: client sync engine. `GameSync.caughtUp(seq)` waits for an action's result seq before a follow-up action (proof then We did it). `sequencer.ts` (pure ordering/gap logic), `engine.ts` (`GameSync`: topics, resync, status, actions), `transport.ts` (backend interface; `supabaseTransport.ts` in the app, fakes in tests), `clock.ts` (server clock offset), `useGameSync.ts` (React hook), `lockout.ts` (stale-state banner), `presence.ts`. Broadcasts carry `prev_seq` per audience so clients can skip the other team's seqs without a fetch.
- Presence (who has the app open) rides on `game:{id}` only; ephemeral, never game state. Clients may insert presence, never broadcasts.
- While not live the game screen is `inert` under a stale-state banner (`StaleBanner`)
- Styling: design tokens are CSS variables in `src/index.css` (names match `docs/design.md`); fonts are bundled via `@fontsource` (Space Grotesk, Inter) and precached by the PWA
- Build version (`src/lib/version.ts`): `v<commit count> · <sha>` on every screen's footer and in Settings; CI checks out full history so the count goes up by one per merge
- Vite `base` is `/hide-and-drink/` (GitHub Pages path); keep asset paths relative to it
- Lazy chunks use `lazyWithReload` (`src/lib/reloadOnStale.ts`): a new deploy's service worker deletes the old version's files under an open app, so a failed chunk load reloads once (max once per 30 s). `ErrorScreen` wraps the app so any crash shows Reload instead of a blank screen
- `src/hiding/`: round logic. `state.ts` (bar + freeze from hider-only events, hiding config, server-time round clock), `bars.ts` (`hiding_bars` + picker list), `useGeolocation`, `usePositionReporter` (seekers every `seeker_location_interval_s` while live). UI: `Round` (hider/seeker views, `TopbarClock`), `BarPicker`. Hider GPS never leaves the phone; `hider_bars` has no client access. Seeker positions go to both teams (both team topics, readable by any player on a team) and show as name-tagged dots; tapping one gives the straight-line distance. Web apps get no background GPS, so seekers share only while the app is open: `useWakeLock` keeps the screen on (toggle on the seeker map, default on), and tags show the age of a stale position. Both teams share the one main clock in the top bar. With several hiders, `choose_bar` is first to lock in; `BarPicker` reports this phone's selection (`report_picking`, on change and every 15 s, null on close) and shows teammates' live picks (`GameSync` `picks`). Hider-only labels use `PrivateLabel` ("Only your team sees this" with 2+ hiders, via `HiderCountContext`)
- Dev/playtest mode: config `dev_mode` (host toggle, off by default) shows a banner and turns GPS off; each player long-presses the map (`GameMap` `onLongPress`) to set their position, kept on that phone. The banner has playtest tools (`PlaytestTools`): `skip_hiding` (any player; hiding period becomes the time spent, then the usual `seeking_started`, whose `at` the clients' round clock follows) and `dev_draw_cards` (hiders, keep-all draw with no question); both refuse `playtest_only` unless `dev_mode`. `usePosition` (`src/hiding/`) is the one source of position for seeker reports (freeze), suggested answers, bar sorting and questions
- `src/map/`: map logic. `style.ts` (MapLibre style built entirely from the city pack: no tile server; street labels from the app's own glyphs; tap shows names), `cityPack.ts` (`get_city_pack`, cached per session), `playArea.ts` (polygons, area, outside mask), `mapLink.ts` (Hide and Seek Map Generator `hzc`/`hz`/`pb`/`url` link import). UI: `GameMap`, `PlayAreaEditor` (Terra Draw), loaded lazily via `lazyMap.ts`. `GameMap` sets MapLibre's worker URL explicitly (bundling breaks its default) and draws overlays (zone circle, candidate bars, people) from props
- Play areas: host draws/edits/imports in the lobby and calls `save_play_area` (server unions, repairs and validates; only the creator can overwrite; seeded areas are saved as new). Areas carry `creator_name` and `created_at` (shown as a "made by" tag). Settings (cog on Home, `Settings.tsx`) lists all saved maps; `delete_play_area` lets any player delete player-made maps, never built-in ones or one an open lobby has chosen
- `src/play/`: in-round logic, pure and tested. `state.ts` (questions, log, due timers from events), `geo.ts` (metre projection, radar circle, thermometer half-plane, point-to-area distance), `shading.ts` (remaining area, ruled-out hatch, suggested answers), `features.ts` (city pack features: nearest feature, closest point, nearest-feature regions, bonus count rules), `overlays.ts` (question tools: circles, candidates with a line to the nearest labelled in km), `timeline.ts` (questions + log merged into the activity timeline), `manualShading.ts`, `photos.ts`. UI: `Round` (bottom tabs, pending question pinned on top; hiding-period bar picker and freeze from `src/hiding/`), `AnswerSheet`, `AskPanel` (tiles in the type colour, `question_types.extra.colour`), `Timeline` (the one activity log, times as the main clock read: `+m:ss` since seeking started, `−m:ss` left to hide (`clockLabel`): question cards with answer, asker, cards drawn/played, photos; Show on map; Shade by hand; curse cards with text, cast cost and payer, status, and the replies/proofs/veto linked by `LogEntry.instanceId`), `ManualShadeSheet`, `DeadlineRing`
- Manual shading: seekers `set_question_shading` (`{mode: keep|cut, area}`, `{mode: none}` or null = back to the app) on any answered question of the round; public `question_shading_set`; `shade` uses it instead of the app's constraint
- Map labels: street names and tool distances use SDF glyphs in `public/glyphs/` (built from the bundled Inter by `scripts/glyphs/build.py`, precached); `mapStyle` only adds symbol layers when given a glyphs URL. Map popups and selected points have "Open in Google Maps" (`MapsLink`, `src/map/googleMaps.ts`)
- Questions: `ask_question` (seekers, after hiding ends, one pending), `answer_question` (hiders; late answers accepted and flagged). Deadline = config `answer_deadline_s.<type>` > question `extra.deadline_s` > `answer_deadline_s.default` > 300 s. No scheduler: `_settle_timers` runs at the start of question actions and from `settle_timers`, which every phone calls when a countdown it shows hits zero; it logs `seeking_started` (status `hiding` → `seeking`) and one `answer_overdue` (shot) per missed deadline. Each option once per run: `ask_question` refuses `question_used` (any question row of the round not host-voided; options with `reusable: true`, the custom radar, aside), and the Ask tab greys used ones out
- Suggested answers are computed on the hider's phone (bar, or GPS inside the bar circle) and never sent anywhere. Shading is computed on each phone from answered questions. No "bars still possible" list, and only the hider sees venue dots during a round (seeker maps pass `hideVenues`)
- Map questions send the seeker's position; the server stores the seekers' side (nearest feature, distance to target, tentacle candidates) in the question's `params`. Answers are text. Answer photos go to the private Storage bucket `question-photos` at `<game_id>/<question_id>/<file>` (hiders upload while that photo question is pending; every player of the game reads)
- `src/cards/`: card state from events (`state.ts`: deck snapshot, hider-only hand and pending draws, effects, time bonus, bans, vetoes, rolls, drink proofs, cast choices). UI: `CardFace` (one template for every card, with an info button opening `CardInfoSheet`: text, cost, veto, `cardDetails`; `CardInfoButton` also on library/deck rows), `HandPanel` (hider Hand tab: keep draws, pick targets/discards/bans, Cast by slide, hand grid with one slot per `hand_limit`), `EffectsPanel` (seeker Effects tab, map strip, hider confirm prompt), `CardExtras` (dice/wheel, Veto button, veto lock banner, ban list, drink proof prompt). `start_game` snapshots the deck (`game_cards`; `config.deck` `{card_id: copies}` overrides library copies) and deals a server-shuffled pile (`card_instances`, no client access). `answer_question` draws the question's reward (hider-only `cards_drawn`); `keep_cards` keeps exactly `pick` (hand limit `config.hand_limit`; discards in the same call may be hand cards or cards kept from this draw, which then never reach the hand). `play_card` (optional `p_choice`) is a front over `_play_card_core`, which handles every behaviour; the front takes `p_choice.media` `{cost, setup}`: files the hiders uploaded to `drink-photos` at `<game_id>/<instance_id>/` before casting (the cast-cost drink photo, the `hider_proof` first step; `castMedia`, attached in `HandPanel` before Cast) and proves those proofs in the same call. Behaviours: text, timed (`start_followup` for `params.followup_s`; a timed card with a follow-on is a task the seekers can also clear like until_cleared until the lock starts), until_cleared (`clear_effect` by seekers, `confirm_clear` by the hider; `blocks_questions` makes `ask_question` refuse `questions_blocked`), next_question_modifier (multiplies the next answer's draw and pick), trivia (`set_trivia` by hiders writes `params.count` questions once, `answer_trivia` by seekers sends an answer for every question not yet right at once, `mark_trivia` by hiders marks all waiting answers at once: wrong ones go back, all right clears the effect; `params.need_right` (Moll: 1 of 3) clears once that many are right, and a set that falls short is deleted (`trivia_marked.reset`) so the hider writes a new one; `force_clear_trivia` host only, either team, marks all right (no button: Fix something's Clear a curse does it); table `trivia_questions` has no client access, everything is in public events; Curse of Moll uses it), question_ban (`p_choice.bans`; `ask_question` refuses `question_banned` for the run) and powerups: veto/randomize close the pending question (`questions.closed_by`; randomize asks a random other unused option of the type, or on types with `question_types.extra.randomize_vetoes` (thermometer) closes it as a veto, payload `as_veto`), duplicate (`p_choice.target`) and discard_draw (`p_choice.discard`, then a keep-all draw) are hider-only events, move reopens `choose_bar` and makes `ask_question` refuse `hider_moving` until a public `hider_moved` (shading ignores answers from before it). Curses with `params.not_applicable` (Escape) start at once and seekers may cancel them while running with `check_curse(false)` (Not applicable button). Curses with `params.seeker_confirm` (a question, e.g. Prison) start `awaiting_seekers` (timed: `ends_at` infinity, nothing blocks, no evidence proof yet) until the seekers answer `check_curse` (public `curse_checked`: yes starts it from now, no clears it); `CurseCheckPrompt` pins it on the seekers' screen. Curses with `params.blocks` (e.g. transport) show a yellow "<Thing> blocked" banner like questions (`otherBlocks`, `OtherBlockedBanners`). Drink cards (`params.drinks`) pin a `DrinkNotice` on both teams' screens until Done and push to the teams that drink. Time_bonus cards are never played (`card_not_playable`): they count only while held in the hand at the end of the round, shown as "+X min" next to the main clock on the hider's phone only. `veto_curse` (seekers, `can_veto` curses): ends the effect, lock = `veto.base_lock_s + veto.step_s × vetoes used` this run, chained after the previous lock. `roll_dice`/`spin_wheel` (any player) for played cards with `params.utility` (wheel needs `params.wheel_options`, else the phone opens `wheel_url`). Drink proofs (`photo_proof_for_drinks`, default on): cast costs (or `params.cost`; always paid by the hiders, curses included; `params.cost_team` overrides; the `drink_due` carries the card's `instance_id`), `params.drinks` teams (only when `params.proof` = `photo`), vetoes and missed deadlines open a `drink_due`; curses with `params.proof` = `photo` or `video` that seekers clear open an evidence proof (`drink_proofs.kind` `evidence`, public `proof_due`) that `clear_effect` waits for (`proof_needed`) and a rejected `confirm_clear` reopens; curses with `params.hider_proof` (Unguided Tourist, Bird Guide, ...) also open a hiders' `setup` proof first (`SetupProofs` pinned for hiders; seekers can't clear until it's in; a rejection never reopens it); `params.hider_proof_prompt`/`proof_prompt` say what to send, and `judge_question`/`judge_accept`/`judge_reject` relabel the hider's confirm (Sculling: "Who drank quicker?" Seekers clears, Hiders reopens) next to both proofs; the hider's side of a question tool is tagged `side: 'hider'` and drawn blue; the team uploads to private bucket `drink-photos` at `<game_id>/<proof_id>/<file>` (photos shrunk to JPEG; videos up to 50 MB, the free plan's per-file cap, squeezed on the phone by `squeezeVideo` if bigger) and calls `submit_drink_proof`; both teams see it in the log, and `ProofToast` pops up on both teams' phones when any proof comes in or is closed by a host fix (push to the other team too). Photo/video pickers use `MediaBox` (no `capture`, so camera, library or screenshots)
- `src/venues/`: per-game venue edits from events (`state.ts`), merged into the pack's `venues` layer for the picker, maps, shading and suggestions. Lobby: no venue editor in the UI (removed as pointless: seekers never see venues); the server still accepts host `add_venue`/`set_venue_hidden` in the lobby, snapshotted into `game_started.venues`. Round: hiders `add_venue` from `BarPicker` ("Not listed?", pin starts at GPS, tap the map to move it, must be inside the play area), hider-only `venue_added`; a trigger on `games` reveals that round's hider venues (public `venues_revealed`, no actor) when the status leaves hiding/seeking or the round changes. Tables `game_venues`, `game_hidden_venues` have no client access. `_valid_bars` = pack + public + revealed + this round's hider venues, minus hidden; `hiding_bars` leaves unrevealed hider venues out for non-hiders
- `src/library/`: shared card library (`library.ts`: rows, deck maths, actions; `params.ts`: the params each behaviour reads, for the editor; `useLibrary`: fetch + live refetch on the `library` Realtime topic, on reconnect and on return to the app). Any player adds/edits/retires cards and categories (`save_card` with `p_base_updated_at` → `card_changed` if someone else saved first, `set_card_active`, `save_category`, `set_category_active`: refuses `category_in_use` while it has active cards). Never deleted; edits record the author on the row and in append-only `library_edits`. `data/cards.json` is only the original seed now (seed inserts `on conflict do nothing`). UI: `CardLibrary` (Settings: library editing; Lobby: deck builder with presets, category tabs with totals, -/count/+), `CardEditor` (one form for any card, live `CardFace` preview), `Stepper`
- Deck: `config.deck` (`{card_id: copies}`, absent = library defaults) is set only by `set_deck` (host, lobby, no freshness check, whole deck per call; the builder debounces taps 500 ms); `update_config` keeps the stored deck. Retired cards in a deck drop out at start. `deck_presets` are shared like play areas (built-in "Library defaults" = null deck; `save_deck_preset` overwrites your own same-named preset; `delete_deck_preset` any player-made one)
- `pipeline/`: Python city-pack builder (GTFS stations, OSM venues/categories, ABS suburbs/LGAs, clipped to play areas + buffer plus the city's `coverage` circles, Brisbane 10 km from the CBD; `save_play_area` refuses areas past the pack extent). Layer rules in `data/map-layers.json` (layer id = question option `source`), city sources in `data/cities/`, hand venue edits in `data/venues/` (`add`, `include`, `exclude` by OSM id). Output `data/city-packs/<city>.geojson`, loaded by migration into `city_packs`/`map_features`; clients call `get_city_pack`
- Host overrides (`docs/overrides.md`: audit of every automatic event and refusal, with its fix): `host_override(kind, params, reason)`. Host does any kind; hiders do the hider-only ones (bar, hand, draw pile, moving a player onto the hiders); a seeker host only files `override_requested` (no details) that a hider carries out with `p_request_id` or declines. Public `override` event (who, what, why; hider-only details in a hiders `override_detail`). Rows changed are captured in `override_changes` and events tagged `payload.override_id`, so `undo` restores rows (`undo_conflict` if changed since). Undo needs both teams: any player asks (their team's yes), a player on the other team agrees (kind `confirm` with `p_request_id`) or either says no (`decline`); `host_override` is a front that handles undo and passes the rest to `_host_override_core`. and phones drop the undone events (`src/overrides/state.ts` `effectiveEvents`, applied in `App.tsx`). Paused timers end at `infinity` (`timer_pauses` keeps the time left). UI: "Fix something" button next to Leave game (`App.tsx`, sheet state passed to `Round`; `FixSomething`, options in `src/overrides/catalogue.ts`), request banner for hiders, "Host fix" rows in the Timeline. New automatic behaviour needs a row in `docs/overrides.md` and an override
- Rounds (`src/rounds/state.ts`, `supabase/migrations/20261219090100_rounds_scoring.sql`): seekers `found_hider` (`FoundButton`: tap, "Are you sure?", slide; seeking only) scores the round into `game_rounds` (hide time from seeking start + time bonuses in hand; no client access, public `round_ended` with score and bar), sets status `round_over` and swaps every team (`team_changed`, no actor). `BetweenRounds` shows result, standings, teams (`set_team` works between rounds); a new hider or the host calls `start_next_round` (logged as `game_started` with `next_round`). Host `end_game` from anywhere (`FinalScreen`; a running round doesn't count); `end_stale_games` (keep-alive job, and every `create_game`) ends games idle 24 h. Player total = sum of rounds they hid; winners = highest total. Overrides `adjust_score`/`redo_round` (host only, `_override_round`, also between rounds; nothing else works then). `_settle_timers` does nothing outside a running round. Join codes are unique only among games that aren't ended (partial index); `join_game` ignores ended games
- `supabase/migrations/`: schema, RLS, action functions, Realtime broadcast trigger; `supabase/tests/`: pgTAP tests
